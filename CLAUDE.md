# Guessoca

"Who am I?" with a post-it on your forehead, for 2–8 friends on a voice call, played on a neon-noir rooftop where everyone walks, jumps and shoves a pixel character. Desktop browser only, keyboard first. Bun workspaces monorepo:

- `packages/rules` (`@guess/rules`): pure TypeScript room and game rules. No DOM, no Pixi.
- `packages/world` (`@guess/world`): pure TypeScript movement, gravity, collision, riding on heads, shove and respawn. No DOM, no Pixi.
- `packages/protocol` (`@guess/protocol`): message types shared by client and server, the room snapshot, the presence frame and the client message parser.
- `apps/web`: Vite + Svelte 5 + PixiJS v8 + dssoca client, hand-written routing (`/`, `/sala/CODE`). Post-its and panels are HTML over the Pixi canvas.
- `apps/server`: Bun HTTP + native WebSocket. The room is a pure state machine `step()` with timers as data; a `RoomHost` owns sockets, timers and the presence relay; `Rooms` holds rooms in memory. Serves the built client. One container on the VPS at guess.passoca.dev (host port 3003).

TypeScript with no server build step; packages export `./src/index.ts`. Tests are `bun test`, written first. CSS classes are prefixed `gs-`. Routes are Portuguese. Commit messages are Portuguese, "Tema: o que faz", no prefixes.

Domain vocabulary is in `CONTEXT.md` (Portuguese canonical terms, English code identifiers). Decisions are in `docs/adr/`. See `README.md` for the current code layout.

The character pack (`assets-src/`) is gitignored by license (ADR 0007): only the sheets generated by `bun run sprites` are committed. Never commit the pack.

Before touching any art (characters, animations, props, backgrounds, maps, emotes, the film look), read `docs/art.md`.

When the owner hands over a character folder ("add this character", "replace X with this"), follow "Art made by an image model" in `docs/art.md`. Never change the pixels of art the owner supplies: only move whole frames, and let the game draw it smaller. The prompt the owner uses to get such folders is `docs/character-prompt.md`.

The owner's system page is `/sistema` (ADR 0009): it lists, previews, downloads and replaces the served files, behind a password. Files replaced there are stored in `data/overrides/` and win over the built ones even after a deploy, so if new art from the repo isn't showing live, check for an active override first. The one-time server setup for its password is in `docs/sistema.md`; never put the password or its hash in the repo.
