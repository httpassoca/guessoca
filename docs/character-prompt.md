# Prompt for a new character

The owner gives this prompt, with reference pictures, to an image model. What comes back is a folder that `tools/sprites/src/pack.ts` can import without changing a pixel (see "Art made by an image model" in `docs/art.md`). The prompt gives a minimum frame count and a duration per animation and lets the model choose how many frames each one needs; the counts it chose come back in `sheet.json`.

The prompt text lives in `apps/web/src/lib/system/character-prompt.txt`, so the system page (`/sistema`) can show it with a copy button. Edit it there.

What the prompt asks for, and why:

- **No game name and no map.** The model only needs to know it's a side-view game with small characters; the owner doesn't want the rest shared.
- **A method, not just rules** ("HOW TO ANIMATE"): list the character's body parts from the references, research pixel-art references of each motion online, plan key poses, draw each frame from the previous one part by part, re-check every frame for missing or changed parts, and animate like pixel art (pose to pose, whole steps, no morphing or blur). It may use subagents: one per animation, one for research, one reviewer. Earlier packs came back with idles that didn't move and bodies that never changed in the air; this section is aimed at that.
- **`attack.png` instead of `shove.png`.** The game's shove is the character's attack, and a character with a weapon uses it. `packFiles` in `tools/sprites/src/pack.ts` takes `attack.png` when the folder has it and `shove.png` otherwise; inside the game the animation is still called `shove`. A compact, hard-edged weapon effect is allowed in the attack only.
- **The preview is an HTML page styled with dssoca** from its CDN, with a fixed feature list taken from a preview the owner liked: a sticky toolbar (pause, step, restart, checkerboard, ground guides, flip, zoom 1–8×, status), a combined sequence on one character with pills, progress and timing, and a grid of the seven animations with live frame counters, one-shots holding their last frame for a second.
- **Research the character, then ask.** For a known character or a real person, the model searches online for how they actually move, above all their signature attack (weapon, named technique, a companion that appears), and makes the attack recognisably theirs. Where the research leaves a choice of taste (two signature moves, with or without the companion), it lists the options, says which it would pick, and asks the owner once before animating.
- **Frame counts are minimums.** No animation has fewer than 8 frames, and the attack has at least 18 (the owner's numbers); the maximum is 16, or 24 for the attack. Each animation has a duration range instead of a fixed fps: the model adds frames where the motion needs them and sets fps = frames ÷ duration, up to 60. Two durations are hard limits from the game: the attack fits in 0.45 s (`SHOVE_COOLDOWN_MS`), so 18 frames play at 40 fps, and the fall lasts 0.33 s (`FALL_MS`). On import, copy the chosen numbers from `sheet.json` into the config with `packSpec({ idle: [frames, fps], … })`; `buildPack` refuses a pack whose attack runs over or whose fall is off (`specProblems`). Packs from before this use `PACK_SPEC`, the old fixed counts.
- **The attack may leave the cell.** `attack.png` alone may use a larger cell (up to three times the normal width) for a long weapon, a lunge or a shot, with the feet on the same ground line; `sheet.json` then gives the attack's `cell_width`, `cell_height`, `ground_y` and `feet_x`. On import that is `cells: { shove: { cellW, cellH, dx } }` in the config, with `dx` = the idle's feet x in the normal cell minus the feet x in the attack cell, and `padX` at least `-dx`. The frame of every animation grows to the attack's reach, so the sheet gets wider; `buildPack` refuses a sheet over 8192 px on a side.
- **Size is in the pixels** ("SIZE AND PROPORTIONS"). The reference is an ordinary adult, 128 px tall in the art and 50 units in the game (Eve, Pinocchio and Vorcaro are that size). The model decides the character's size as a multiple of that from a table (a dog is 0.30–0.45, knee to mid-thigh; a giant at most 1.5), draws it at `size × 128` pixels, never squashes width, and writes `size` and `standing_height_px` in `sheet.json`. It proposes the size itself instead of asking. On import every pack that followed this uses the same scale, `PACK_WORLD_SCALE` (50/128) in `tools/sprites/src/pack.ts`; a test ties the prompt's numbers to those constants.
- **Four designs first.** The first step is one image with four alternative idle frames, A to D, each next to a grey 128 px human silhouette with its size written under it, and the model asks which to use. The preview page also shows the idle beside that silhouette.
- Rule 6 forbids a last loop frame that copies the first (Vorcaro's idle and walk had one), and rule 8 asks for binary alpha outright.
